- One gap at a time, in the order the architect set: INFRA-8204, INFRA-8207, INFRA-8201, INFRA-8202, INFRA-8198.
- Each gap is dispatched to the fleet on cuphead (`chump dispatch <GAP> --auto-merge --skip-tests --backend headless --model sonnet --paths <csv> --prompt <brief>`) through `~/phase-r/dispatch.sh`, which guards on load1 < 12 and on no agent of ours already running in that gap's worktree, with `CHUMP_SUBAGENT_BUDGET_S=1800`, `CARGO_TARGET_DIR=/home/ubuntu/chump/target`, `FAST=1 SKIP_TESTS=1 NO_LOCAL_BUILD=1`.

- The dispatch ship phase (`scripts/coord/bot-merge.sh`) is left to run and its outcome is the measurement. When it fails, the failure class is recorded and the fleet-authored commits are shipped from the worktree with the ship tool in recovery mode under the worktree's own session id (`~/phase-r/salvage.sh`: rebase onto origin/main, `CHUMP_BOT_MERGE_RECOVERY_MODE=1 bot-merge.sh --gap <GAP> --auto-merge --fast`). Never `--admin`, never `--no-verify`.
- The node binary is whatever `chump-node-refresh.timer` installed to `~/.cargo/bin/chump` (green-main pinned); the main checkout `~/chump` converges to origin/main HEAD on the same timer, which is how merged `bot-merge.sh` changes reach the next dispatch.
- Verification is on the node with `sqlite3 ~/chump/.chump/state.db`, never from a dashboard.
