# scripts/ci/no-title-regex-gap-closers-allowlist.txt
# CREDIBLE-1550 (Phase R R2, AC4). Files that the TIER-2 co-occurrence heuristic
# in test-no-title-regex-gap-closers.sh flags because they BOTH parse gap IDs
# from PR titles/commit subjects AND close a gap somewhere in the same file.
#
# Two kinds of entries live here:
#   - genuinely-legitimate: parse the title only for dispatch/respawn/display,
#     never to CLOSE (the close routes through the gap_prs FK or a non-title
#     source). These stay allowlisted.
#   - KNOWN PRE-EXISTING closers still deriving the closed gap from the title.
#     These are tracked for conversion to the gap_prs FK; REMOVE the entry when
#     the conversion ships so the gate goes back to true zero.
#
# One repo-relative path per line, then a reason. Mirrors the raw-gh-allowlist
# idiom (scripts/ci/raw-gh-allowlist.txt).
#
# CREDIBLE-1551 (Phase R R2, AC2) emptied this file to TRUE ZERO. The two
# KNOWN PRE-EXISTING closers that used to live here —
#   - scripts/ops/stale-pr-reaper.sh   (INFRA-674 "ghost-status" block)
#   - scripts/coord/chump-pr-triage.sh (`--apply ship-gap`)
# — now resolve the gap they close from the typed gap_prs FK via
# `chump gap gaps-for-pr`, never from a PR title. They still parse titles for
# respawn/retire dispatch and the advisory triage table, but those usages sit
# far from any close, so the proximity-based TIER-2 heuristic no longer flags
# them without an allowlist entry. Keep this file empty of paths: a new entry
# means a new title-regex closer slipped in — convert it to the FK instead.
