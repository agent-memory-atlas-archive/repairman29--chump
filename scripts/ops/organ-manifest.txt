# ChumpOS organ manifest — desired systemd state on the PRIMARY node (helsinki).
#
# The single repo-declared source of truth for which ChumpOS organs must be
# RUNNING and which auto-pagers must stay OFF. scripts/ops/organ-reconcile.sh
# reads this file and makes the node's live systemd state match it — the first
# slice of reproducible-deploy (RESILIENT-305 / RESILIENT-000 self-healing).
#
# WHY THIS FILE EXISTS (2026-08-13 incident): auto-pager DM spam kept
# resurrecting because failed organs were hand-managed and install-helsinki-atc
# re-enabled them every 5 min; the fix landed as HOST-LEVEL systemd drop-ins
# (/etc/systemd/system/*.d/zz-autopage-off.conf) — a NEW snowflake invisible to
# the repo, and the deploy mirror's `git reset --hard origin/main` silently
# reverts any working-tree fix. Declaring desired state HERE, in the repo, and
# having the reconcile re-apply it on a timer converges the node to the repo
# automatically and survives the reset.
#
# Format: one directive per line, "<state>  <unit>  [role=ROLE] [requires=SPEC,SPEC,...]".
# Blank lines and lines beginning with '#' are ignored. Two states:
#
#   enabled     <unit>  → this organ must be enabled AND active. The reconcile
#                         runs `systemctl enable --now <unit>` if it is not
#                         already active. (A no-op when it already is.)
#
#   paging_off  <unit>  → this is an auto-pager that MUST stay silent. The
#                         reconcile installs a repo-declared drop-in
#                         (/etc/systemd/system/<unit>.d/zz-organ-reconcile-pager-off.conf)
#                         that neuters ExecStart to /bin/true, then stops the
#                         service if it is running. The drop-in wins over the
#                         tracked/host unit's ExecStart, survives
#                         install-helsinki-atc.sh's `cp -f` of the base unit
#                         (the .d/ dir is untouched) AND survives the mirror's
#                         `git reset --hard` (its content is re-applied from
#                         this repo, not a one-time host edit).
#
# RESILIENT-347 (per-node-applicable reconcile): `enabled` lines may declare
# two optional fields, space-separated after the unit name:
#
#   role=brain|muscle|data|janitor|trust
#                            LOAD-BEARING classification that scopes per-role
#                            bring-up (RESILIENT-746 / RESILIENT-1055). A fresh
#                            `chump-node-install --role brain` places+enables
#                            every organ tagged brain,data,janitor,trust; a
#                            `--role muscle` node runs ONLY the muscle-tagged
#                            worker (the coordinator/merge organs are brain, so a
#                            muscle node never spins up a SECOND merge driver —
#                            the single-driver invariant RESILIENT-1054 fought
#                            for). CJ's own timer reconcile is unfiltered (whole
#                            manifest) so the tag never changes what a live node
#                            already runs — it only shapes fresh bring-up.
#                            brain=decision/coordination/merge, muscle=builds
#                            gaps, data=publishes state, janitor=housekeeping,
#                            trust=calibration. Also surfaced on every
#                            applicability/backoff ambient event. Defaults to
#                            "brain" if omitted.
#
#   requires=SPEC,SPEC,...   Comma-separated preconditions that must ALL hold
#                            on THIS node before the reconcile will even
#                            attempt to enable the organ. Missing a
#                            precondition is NOT an error — it means the organ
#                            is simply not applicable to this node (e.g. a
#                            Rust helper binary that isn't built there yet),
#                            and the reconcile skips it silently (one
#                            organ_reconcile_not_applicable event, no retry
#                            churn). Supported spec kinds:
#                              bin:<name>   `command -v <name>` must succeed
#                              env:<VAR>    $VAR must be a non-empty env var
#                              dep:<unit>   another systemd unit must already
#                                           be active
#                              file:<path>  a file/dir must exist on this node
#                                           (RESILIENT-1055; a leading ~/ or
#                                           $HOME/ expands against the effective
#                                           HOME). For organs that only apply
#                                           where a host-specific asset lives —
#                                           e.g. the CJ-legacy hand-installed
#                                           chump-cj-* units, whose ExecStart
#                                           points at a /home/<user>/cj-*-run.sh
#                                           that exists only on that one box and
#                                           has no tracked unit file, so a fresh
#                                           `--role` bring-up must SKIP them
#                                           (not `enable --now` a file-less unit
#                                           into an eternal backoff).
#
# INFRA-7764 (docs/strategy/ONE_COMMAND_INSTALL.md section 1, one-command-
# install BOM unification, INFRA-7756): `enabled` lines may also carry
#
#   platforms=SUPERVISOR,SUPERVISOR,...
#                            Comma-separated list of supervisors this organ
#                            applies to: systemd|launchd|runit. Omitted means
#                            "platforms=systemd" — the implicit assumption
#                            every line in this file carried before this
#                            field existed, so no pre-existing line's
#                            behavior changes. organ-reconcile.sh (systemd
#                            only) filters ENABLED to lines whose platforms
#                            include "systemd" before doing anything else,
#                            via organ_platform_matches()/organ_current_
#                            platform() in organ-manifest-lib.sh. This is
#                            what lets bootstrap-manifest.yaml's macOS-only
#                            capabilities (curator/self-doctor/paramedic/
#                            conductor/etc, INFRA-7765) fold into THIS file
#                            as platforms=launchd lines — visible in the one
#                            declared roster instead of a second file nobody
#                            diffs against the first — without this
#                            reconcile ever attempting to `systemctl enable`
#                            a unit name that only ever existed as a launchd
#                            plist.
#
# INFRA-7766 (docs/strategy/ONE_COMMAND_INSTALL.md section 1, same slice):
# `enabled` lines may also carry
#
#   housekeeping=<script>|<cadence>|<args>
#                            Pipe-separated triple identifying this organ as
#                            one of install-node-housekeeping.sh's supervised
#                            loop-services: <script> is the repo-relative
#                            path it runs, <cadence> is the sleep interval in
#                            seconds (0 = the script self-loops, e.g. the
#                            orchestrator), <args> (may be empty) are extra
#                            CLI args appended to the script invocation.
#                            scripts/ops/lib/node-housekeeping-roster-lib.sh's
#                            housekeeping_organs_from_manifest() reads this
#                            token from every `enabled` line to derive
#                            install-node-housekeeping.sh's install roster —
#                            so THIS file, not a hardcoded heredoc in that
#                            script, is the one declared source for which
#                            organs it installs. Omitted means the line is
#                            not a housekeeping organ (most `enabled` lines
#                            aren't — housekeeping= only tags the janitor/
#                            brain subset install-node-housekeeping.sh
#                            supervises). If the manifest is missing OR
#                            carries zero housekeeping= lines, the roster lib
#                            WARNs on stderr and falls back to its built-in
#                            10-organ roster rather than silently installing
#                            nothing — deliberately fail-open where the
#                            parser/renderer (platforms= above) fail closed.
#                            Two organs (pr-lander, rot-reaper) are a
#                            documented carve-out NOT given housekeeping=
#                            tokens here — see node-housekeeping-roster-lib.sh
#                            and INFRA-7772 for the unit-name collision this
#                            avoids.
#
# See docs/ops/ORGAN_MANIFEST_BOM.md for the full unified-BOM usage guide:
# how the three consumers (this reconcile, render-organ-roster.sh,
# install-node-housekeeping.sh) read this ONE file, and how to add a new
# organ / new platform / new housekeeping organ to it.

# Applicability is the FIRST gate (blast-all -> per-node-applicable, was
# RESILIENT-347's core ask). If an organ IS applicable but `enable --now`
# either fails outright or the unit is not verified active a few seconds
# later, the reconcile does NOT leave it to fail identically every single
# cycle (the pre-347 churn that re-installed 4 broken units every 5 minutes
# on CJ: integrator/sla-scorecard/backlog-sync-writer/farmer). Instead it
# disables the unit and records a cooldown backoff
# ($CHUMP_ORGAN_RECONCILE_BACKOFF_DIR/<unit>.json, default 1h via
# CHUMP_ORGAN_RECONCILE_BACKOFF_COOLDOWN_S) so the SAME broken unit is only
# retried once the cooldown expires, not every tick.
