# operator-escalation-registry.txt — RESILIENT-274 escalation discipline.
#
# Operator decision (Jeff, 2026-08-10): "don't hear from the fleet unless it's
# way out of line or we don't have a playbook for it." This file is the playbook
# ledger that notify-operator.sh consults: QUIET by default, page the phone only
# for halt-class or novel (no-playbook) signals.
#
# Format:  <signal-kind><TAB>suppress|page|direct   (# comments + blank lines ignored)
#   suppress = has an auto-heal/runbook → log it, DON'T DM the operator.
#   page     = no automated remedy / operator must decide → DM the phone AND
#              emit an operator_paged escalation event (counts against the
#              page-rate vital sign in scripts/ops/vital-signs.sh).
#   direct   = NOT an escalation — a normal DM the fleet OWES the operator (e.g.
#              the Advisor's answer to a Jeff DM). DELIVER the message, but emit
#              operator_direct_message instead of operator_paged so it never
#              inflates the page-rate metric or trips the cry-wolf watchers.
#              (INFRA-3835: without this, every advisor reply defaulted to PAGE
#              and fired a spurious operator_paged on top of the real answer.)
# A kind NOT listed here defaults to PAGE (fail loud — an unknown signal is, by
# definition, one we have no playbook for). CHUMP_NOTIFY_SEVERITY=halt always pages.
#
# When you add an auto-heal/runbook for a signal, add it here as `suppress` in the
# SAME change — that is how a playbook "silences" its own alert honestly.
